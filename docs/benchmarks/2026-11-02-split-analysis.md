# 两池拆单实验：固定区块结果（#30）

## 结论

算法能够自动决定拆单或保留原路径。本轮 **90/90 组成功，35 组选拆单、55 组保留原路径，
没有输出低于基线的样本**。SHIB 六组全部改善；大额 WETH→SHIB 比单路径多约 1.0723%，
反向最大档多约 0.4812%。这些是毛输出提升，不是扣除 gas 后的净收益。

实现：[两池优化器说明](../SPLIT-ROUTING.md)。原始依据：
[完整 90 组报告](2026-11-02-split-mainnet.md)、[JSON](2026-11-02-split-mainnet.json)。

## 状态与比较口径

- 所有报价固定在 Ethereum 区块 **26325207**。
- 区块哈希：`0x6552f10c25fe99a05f776bc5e0dfac98907ee9af3d2de1002ffeda9b94aec40c`，运行结束再次核对未改变。
- 原有 30 个方向 × 3 档固定 raw 输入，共 90 组；没有删除无收益样本。
- 同一图、同一报价源、同一快照下，先计算现有 Router 的完整最佳单路径，保留多跳与转换能力，
  再运行两池搜索。不能把基线替换成较弱的“最佳直连池”。
- 图包含 209 个 AMM 池、1 个 wrapper link、48 个代币、432 条边。
- 首版拆单分支为两个不同的 Uniswap V2/V3 或 ShibaSwap V2 直连池，最多搜索按全额报价排序的 4 个池。
- 本轮是内部单路径/拆单对照，没有请求 ParaSwap。不能拿之前不同区块的 ParaSwap 结果直接相减，
  宣称已经追平或超过聚合器。

## 成本不能忽略

| 指标 | 单路径阶段 | 拆单搜索新增 | 完整流程 |
|---|---:|---:|---:|
| 延迟 p50 | 1315 ms | 2171 ms | **3451 ms** |
| 延迟 p95 | 1862 ms | 2921 ms | **4697 ms** |
| 报价阶段实际 RPC 请求 | 4721 | 3727 | 8448 |

延迟的分位数不能简单相加；完整流程值来自逐行实际总耗时。新增适配器报价调用共 5152 次，
其中实际 RPC 为 3727 次，不能把 V2 本地计算或缓存命中都算成网络请求。另有发现 RPC 287 次、
预热/区块设置 RPC 39 次，最后的区块哈希验证单独发生；GraphQL 不计入这些 JSON-RPC 指标。

因此目前适合作为可检查的实验能力，尚不能仅凭“毛输出更多”就默认用于所有线上小额报价。
正式服务接入、额外 gas 的净收益比较与更精细的搜索调度，都需要后续单独定义。

## 参数校准：默认档与更细网格

两档均固定同一区块、同一池覆盖，六个 SHIB 单路径基线输出相同。默认档：10 段粗搜、
4 段局部细化、2 轮、最多 128 次新增报价；加密档：20/8/2，最多 512 次新增报价。

| 指标（6 个 SHIB 样本） | 默认档 | 更细网格 |
|---|---:|---:|
| 成功且完成配置内搜索 | 6/6 | 6/6 |
| 最大相对单路径提升 | 107.2347 bps | 107.2932 bps |
| 新增适配器报价 | 543 | 1416 |
| 新增 RPC | 266 | 702 |
| 搜索耗时 p50 / p95 | 1859 / 2368 ms | 4393 / 5263 ms |

更细网格在本组数据中的额外提升很小：最大样本从 107.2347 增至 107.2932 bps，新增 RPC
却约为默认档的 2.64 倍。因此保留默认档作为首版建议，具体参数仍可通过 CLI 调整；这不是
所有市场状态下的最优参数证明，延迟也只是各一轮实测。

证据：[默认档报告](2026-11-02-split-shib-calibration.md)、[默认 JSON](2026-11-02-split-shib-calibration.json)、
[更细网格报告](2026-11-02-split-shib-dense.md)、[更细 JSON](2026-11-02-split-shib-dense.json)。
