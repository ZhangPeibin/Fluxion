# 2026-11-02 主网基准测试分析

## 结论

Fluxion 已经具备可测量、可演示的 v1 路由报价能力：本轮 90 组报价全部成功，中位输出差距
约 −0.022%，81.1% 的样本落在 ParaSwap 的 ±0.5% 范围内。但延迟与大额交易的尾部质量
仍有明显差距，不能据此宣称与聚合器全面持平。

原始依据：[完整报价表](2026-11-02-mainnet.md)、[JSON](2026-11-02-mainnet.json)。

## 实验设置

- Ethereum 主网，区块范围 26324182–26324194。
- 30 个有方向的交易对 × 3 档固定 raw 输入金额，共 90 组。
- 同一组两边输入完全相同；金额档位不是按当天价格重新换算的美元金额。
- Fluxion 使用 `config.benchmark.yaml`：最大 3 跳、每个状态保留 8 个候选，
  `max_pools=10000`，默认双币/全币白名单、流动性下限 50000。
- 实际发现 29 个 V2、169 个 V3、5 个 Curve 池，共 203 个池、48 个代币、418 条有向边。
- Fluxion 为本地 debug 构建，公共 RPC；对手为 ParaSwap 公开价格接口。
- 1inch、0x 因未配置密钥跳过，不计作失败。

## 汇总

| 指标 | Fluxion | ParaSwap |
|---|---:|---:|
| 报价成功 | 90/90 | 90/90 |
| 延迟 p50 | 944 ms | 381 ms |
| 延迟 p95 | 1629 ms | 827 ms |

输出差值公式：`(Fluxion 输出 − ParaSwap 输出) / ParaSwap 输出 × 10000`，单位为基点。

| 输出质量指标 | 结果 |
|---|---:|
| 中位差值 | −2.224 bps（约 −0.022%） |
| 平均差值 | −132.687 bps（约 −1.327%） |
| 差值在 ±50 bps 内 | 73/90（81.1%） |

平均值比中位数差得多，意味着少数大额交易存在严重损失，不能只展示中位数。

| 方向与输入 | Fluxion 输出 | ParaSwap 输出 | 差距 |
|---|---:|---:|---:|
| 1000 USDC → WETH | 0.436129387972290177 WETH | 相同 | 0% |
| 100000 USDC → DAI | 99991.413759296998584473 DAI | 相同 | 0% |
| 33.333… WETH → stETH | 25.659659726469924242 stETH | 33.338153972388848567 stETH | −23.032% |
| 100000 USDC → stETH | 25.659660302031919040 stETH | 43.592462397902306984 stETH | −41.137% |
| 33.333… WETH → SHIB | 12636485237.395973622493515268 SHIB | 15597920861.850508329738992465 SHIB | −18.986% |

JSON 中 stETH 样本的 ParaSwap 平台包含 `wsteth` 和 `uniswapv3`，而 Fluxion 使用 V2/V3
池子；当前图没有 stETH↔wstETH 的协议转换边。这是可直接观察到的能力差异。SHIB 的
差距可能涉及池覆盖、候选剪枝、拆单或流动性深度；仅凭本轮数据无法把原因唯一归结到其中一项。

## 与历史记录的关系

旧记录：成功 86/90，中位 −4.3 bps，62/86 在 ±50 bps 内，延迟 p50/p95 为 981/1814 ms。
本轮这些汇总指标更好，但两轮区块、时间、配置与统计口径并不完全相同，不能把变化全部
归因于本次代码改动。做严格优化实验时，应在接近的市场状态下对照同一语料与配置。

## 边界与求职展示

- 报价按顺序读取实时状态，外部接口不能固定区块；区块范围用于披露偏差，不表示可精确重放。
- 比较的是输出数量，不含 gas、成交概率、MEV 或实际执行。
- Fluxion 是有界候选搜索后精算，不保证找到整个市场的全局最优路由；没有拆单。
- 这是一轮 90 样本实验，不是长期可靠性或生产延迟 SLA。

适合面试的表述：实现了 Rust 多协议路由服务，建立了固定语料的主网基准测试，量化了成功率、
报价偏差与延迟，并能根据原始路由信息解释部分大额交易的能力缺口。
