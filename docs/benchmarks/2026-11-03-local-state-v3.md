本记录验证 V3 数学、状态隔离和受限池集性能。**不是原全平台 90 行的同轮优化对照**；
当前本地模式尚不支持 Curve/wstETH，默认服务仍使用 RPC 模式。

## 真实 HTTP 四池样本

运行 `config.local-v3.example.yaml`，使用真实 Graph 发现，`/info.mode=mainnet`，四个
WETH/SHIB 池。单机循环 20 次请求，均输入 33.333… WETH，`split=true`。

- 20/20 成功，均使用区块 `26330938`、hash
  `0xff72e0cfc67b6fa45e4bd9ec9032ddadb75de3a4f65f8738c08bc23999ac12e2`。
- HTTP p50 **31.053812 ms**，p95 **31.326041 ms**（nearest rank）；包含 JSON 和本机 HTTP。
- 三分支分配 70% / 15% / 15%；raw 输出 `15737723070189123540855002679`，基线
  `15466986065178680290106170074`。
- 响应的 baseline/additional RPC 均为 0，V3 coverage 包含 173 和 149 个 initialized ticks。
- CPU worker 有界，后台负责状态更新。本次短样本不构成长时间并发、内存或全图 SLA 证明。
- 后续 readiness 观察到区块 `26330958`、已发布版本 22、4/4 池且 lag 0，确认 V3 窗口也持续随新区块重建。

公共 RPC、debug 构建。不能将这些数字与旧全图四方实验的 4–6 秒直接计算无损提速倍数。
当前效果说明移除请求内 Quoter RPC 的方向有效；完整覆盖回归仍须后续阶段完成。

## 失败语义与范围

window 内每个置位 bit 都必须有对应 tick；越过已装载 word 返回 SnapshotIncomplete。
即使 V2 路径可成功，整个相关请求也不能隐瞒 V3 状态缺失；不会转成请求内 RPC。
本阶段没有实现自动按请求拓展窗口或日志增量重放。详细说明见 [LOCAL-STATE](../LOCAL-STATE.md)。
