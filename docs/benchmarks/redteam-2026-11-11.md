# Security red-team benchmark (11 Nov 2026)

Scope: local adversarial corpus against `transaction.inspect` and `signature.inspect`, using
Foundry contracts on a local Anvil node. This is a regression/red-team corpus, not a certification.

## Environment

| item | value |
|---|---|
| machine | Apple M2 |
| OS | macOS 27.0.1 |
| Foundry | 1.9.0 |
| Anvil | 1.9.0, `--chain-id 56`, `127.0.0.1:8546` |
| Fluxion | installed `fluxion` binary |
| RPC | local Anvil |
| Solidity | 0.8.24 |

No mainnet transactions, private keys, or external RPCs are used. The Anvil default test key is
used only to deploy/fund local contracts.

## Lab

Foundry project: `tests/security/`

| contract | purpose |
|---|---|
| `TestERC20` | benign transfer/approve controls |
| `FeeOnTransferERC20` | 10% fee, emits two Transfer logs |
| `FakeLogERC20` | emits Transfer/Approval without changing balances |
| `TestERC721` | NFT operator approval |
| `MulticallHelper` | hidden nested approve |
| `EIP1967Proxy` | implementation slot and `upgradeTo` |
| `SwapRouterStub` | V2-style swap calldata |
| `DelegatecallAttacker` | hidden delegatecall, unknown selector |
| `BenignTarget` | unverified benign target |

Reproduce:

```bash
python3 bench/security/redteam.py --out /tmp/redteam.md --json-out /tmp/redteam.json
```

The harness deploys via `forge create`, runs the installed CLI, records findings/risk/coverage and
latency, and stops Anvil if it started it.

## Summary

- Controls: **2/2** with no findings.
- `detect` cases: **13/13** matched the expected rule IDs.
- Known gaps: **2/2** explicitly classified, not hidden.
- Local Anvil latency: ~5–12 ms per case.

### Effect verification

`transaction.inspect` now re-simulates the target call plus `balanceOf` / `allowance` reads in one
`eth_simulateV1` block state. It compares the post-state with the pre-state at the same pinned block.

- `EFFECT-007`: Transfer log amount differs from the actual balance delta.
- `EFFECT-009`: Approval log differs from the actual allowance.
- `EFFECT-010`: NFT Transfer log differs from `ownerOf` (implemented, not covered by a contract in
  this corpus yet).

This turns `FakeLogERC20` and fake approvals into detected high-risk cases.

### Known gaps

1. **Hidden delegatecall**
   - `DelegatecallAttacker.claim(address,bytes)` has an unknown selector; the actual danger is inside
     a delegatecall that succeeds during simulation.
   - Current result: `decode=partial`, simulation succeeds, no finding.
   - Required fix: trace/internal-call inspection or a code-level policy allowlist.

2. **Unverified benign target**
   - No verification provider is configured, so `verified=null`.
   - `CONTRACT-001` is intentionally not emitted for missing data.
   - Required fix: source-verification provider; missing verification must stay unknown.

## Limitations

- The corpus is local and synthetic; it is not an independent mainnet exploit sample.
- Fake logs are now detected for tokens with callable `balanceOf`; non-standard tokens still degrade to unknown.
- No full trace/state diff: hidden delegatecall and internal transfers can be missed.
- UserOp `callData` and signatures are not decoded by `signature.inspect`.
- V3/aggregator swap routers and non-EIP-1967 proxies are not covered.
- Known-gap cases do not fail the run; they are reported for remediation.

## Decision

Keep the local red-team harness as a release gate for detector regressions. Do not claim real-world
security coverage from this corpus. Balance/allowance verification is now the baseline; the next
remediation item is internal-call tracing.
