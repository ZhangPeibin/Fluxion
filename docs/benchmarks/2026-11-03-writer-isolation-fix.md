## 工程验证与实现

写侧由每个 SnapshotStore 的单个有界 blocking worker 承担；网络 future 仍使用应用持有的
Tokio runtime handle，但构造、位图处理、校验与回收不占用 I/O worker。最多一个调用运行或
等待；上次取消的 worker 未退出时仅允许一个重试等待，额外调用立即拒绝，等待也计入截止。

取消由 RAII guard 通知运行中的任务；CPU 未退出前持有 writer 名额，不能被 abort 提前释放。
最终取消/截止检查在取得发布锁后完成，与短时间原子发布线性化，超时结果不得迟到发布。
旧快照由写侧持有退役引用；所有读者离开后由写侧通过 Arc::try_unwrap 回收，释放不在发布锁内。

两处 bitmap 扫描改为跳过全零 words、按升序只遍历置位 bits；完整对应检查、非法 word、
缺失 tick、重组与新鲜度保护保持生效。

受控写侧 CPU/发布锁场景先在缺陷实现上失败，再验证修复后的 HTTP 旧快照读取、超时、
取消、队列有界与回收。全范围 V3/V2 主网组合逐跳核对通过：区块 26332979，hash
`0xa2bd331485551d1352cc5a5783794158885de16a5c195b4f0a7501af98cda7bf`；
另有 30/30 V3 原始整数输出与独立 QuoterV2 一致。
