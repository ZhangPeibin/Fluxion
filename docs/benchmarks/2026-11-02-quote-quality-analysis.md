# 协议转换与 ShibaSwap：实现和基准结果

## 结论

本轮完成了可配置的 stETH↔wstETH 转换、ShibaSwap V2 接入，以及保证新能力路径不会在
精算前被另一类路径全部挤掉的候选分组。重测后：**全部 15 个 stETH 相关样本、6 个 SHIB
样本的输出，都高于同轮关闭新能力的对照实例**。

stETH 的大额严重偏差已在本轮样本中消除。SHIB 的大额偏差显著缩小，但还存在约 1.9%
的样本差距；保存的原始路径已能证明对手在拆单，并使用了当前白名单之外的中间代币。

依据：[完整表格](2026-11-02-quote-quality.md)、[原始 JSON](2026-11-02-quote-quality.json)、
[实现说明](../QUOTE-QUALITY.md)。

## 实现内容

1. **wstETH 池已经存在**：原语料中的 wstETH↔WETH 六组报价再次与 ParaSwap 完全相同。
2. **协议转换**：配置声明已支持的接口类型和部署实例，目前实现 `wsteth`。
   精算调用协议的整数转换方法，支持独立启用 wrap/unwrap；每次转换计一跳。不是静态 1:1，
   也不把转换当作有储备、收 AMM 手续费的池子。新增不同接口类型仍需相应代码适配器。
3. **ShibaSwap V2**：工厂按白名单代币对批量发现，校验币序/储备、估算流动性并过滤排序。
   本轮加载 6 个符合条件的池；新增平台身份，复用已与链上 Router 对照通过的 0.3% V2 数学。
4. **候选分组**：普通路径、含转换、含 ShibaSwap、两者都有，最多四组；每个 token/hop/组
   保留 top-K。精算并发保持 16，所有候选最后仍按实际输出择优。
5. **展示与证据**：API 增加 swap/wrap/unwrap 操作标记，Viewer 支持新平台和转换虚线；
   基准 JSON 保存双方完整路径、对手池地址/拆单比例，支持同轮功能开关对照。

## 为什么做了两轮

[初次接入结果](2026-11-02-quote-quality-initial.md)中，stETH↔WETH 已追平，但转换加多跳的
USDC/LDO 路径仍可能被现有 spot-price 剪枝挤掉，100000 USDC→stETH 的大额偏差仍在。

分段实测证明更好的三跳路径真实存在；随后补了候选能力分组，以及两个 `top_k=1` 的反例测试：
转换路径不被虚高 spot 的薄 AMM 路径挤掉，新增薄 ShibaSwap 池也不挤掉原有深池路径。
最终重新运行完整语料。首轮数据保留，不作为最终结果宣传。两轮市场状态不同，不用它们
之间的数值差异单独证明算法修复的因果效果；修复依据是分段路径和确定性回归测试。

## 最终实验设置

- Ethereum 主网区块范围：**26324635–26324658**。
- 原有 30 个有方向的交易对 × 3 档固定 raw 输入，合计 90 组；没有为好看而删样本。
- 新实例：209 个 AMM 池 + 1 个 wrapper link，48 个代币、432 条边。
- 对照实例：原有 203 个池，48 个代币、418 条边，明确关闭 ShibaSwap 与转换。
- 两者使用同一 binary、相同基础阈值、最大 3 跳、top-K=8；交替先后询价，再询问 ParaSwap。
- 本地 debug 构建、公共 RPC；1inch/0x 缺少密钥，跳过，不算失败。
- 元数据保留实际配置、源码指纹、dirty 状态、区块范围和逐行时间戳。

## 汇总

差距为 `(本地输出 − ParaSwap 输出) / ParaSwap 输出`；负数表示少换到代币。

| 指标 | 关闭新能力的对照 | 新实例 |
|---|---:|---:|
| 成功报价 | 90/90 | 90/90 |
| 全量中位差距 | −0.0148% | **−0.0070%** |
| 全量平均差距 | −1.3372% | **−0.1018%** |
| 差距在 ±0.5% 内 | 72/90（80.0%） | **84/90（93.3%）** |
| 延迟 p50 | 1085 ms | 1246 ms |
| 延迟 p95 | 1586 ms | 1871 ms |

| 分组 | 样本数 | 对照中位差距 | 新实例中位差距 | ±0.5% 内：对照→新实例 |
|---|---:|---:|---:|---:|
| stETH 相关 | 15 | −1.6065% | **0%** | 4→14 |
| SHIB 相关 | 6 | −1.5109% | **−0.1386%** | 2→4 |
| 其他 | 69 | −0.0070% | −0.0070% | 66→66 |

stETH 分组没有大额负向离群点：唯一超出 ±0.5% 的样本为正差距，不能将其解释成实际成交
优势，仍可能受对手缓存、报价时序与路径能力影响。SHIB 六组全都改善，但最大的两组仍未
进入 ±0.5% 范围。

## SHIB 剩余差距：有实际路径证据

33.333… WETH→SHIB 的 ParaSwap 返回拆单比例大致为：

- 66%：ShibaSwap SHIB/WETH 直连池；
- 14%：Uniswap V2；
- 16%：两个不同费率的 Uniswap V3 池（14% + 2%）；
- 4%：ShibaSwap 的 WETH→BONE→SHIB 路径。

原始输入份额和输出均保存在 JSON 的 `paraswap.route[].swaps[].swapExchanges[]` 中，
展示百分比存在舍入。BONE 地址为 `0x9813037ee2218799597d83d4a5b6f3b6778218d9`，另已通过
链上 `symbol()` 确认为 BONE。它目前不在默认白名单中，白名单过滤没有为追逐单个样本而取消。

所以，“增加 ShibaSwap”确实解决了大部分缺失流动性问题，但不等于拥有对手的拆单与全部
中间代币覆盖。后续若继续追平，应分别评估拆单收益和白名单扩展；本轮没有悄悄纳入拆单。

## 回归与代价

全部 90 组中，新实例相对对照为 **21 组输出更多、68 组完全相同、1 组略少**。
略少的一组是 1400 UNI→USDC，约低 1.7 bps。两边选中了相同的两个 V3 池，第一跳输出
完全相同；差异发生在相同输入的第二跳 RPC 返回中，说明本轮存在实时状态偏差，不能把
这条直接归因为候选剪枝丢路，也不能宣称这轮是严格同区块无回归实验。

更丰富的候选和协议调用增加成本：p50 约增加 15%，p95 约增加 18%。这是本轮报价质量提升
的实际取舍；不能只展示输出改善而省略延迟。

## 验证与边界

- 58 项离线测试通过；9 项主网只读集成测试通过（包括固定区块的 wrapper 和 ShibaSwap 对照）。
- 严格 Clippy、格式检查、Rust binaries 构建和前端生产构建通过。
- 例行审查修复了 `max_pools` 截断应保留深池的问题；候选分组有行为反例测试保护。
- 仍为单路径、报价服务，不构建或发送交易。无 gas、MEV、授权或实际成交比较。
- 外部接口和本地快照不固定同一区块；这是一轮可复查的配对实验，不是长期 SLA 或全市场最优证明。
